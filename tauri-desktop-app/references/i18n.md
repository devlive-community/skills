# Internationalization

Supported locales start with `zh-CN` and `en-US` (`fallbackLng: 'en-US'`). Adding a language must only require new JSON files.

## Namespaces

| Namespace | Content | Location |
|-----------|---------|----------|
| `app` (default) | host UI: nav, settings, about, quit dialog, update dialog, task center | `apps/desktop/src/locales/<lng>.json` → `app` |
| `common` (fallback) | shared words (`copy`, `clear`, `saved`, `download`), shared `errors.*`, shared `logs.*`, `resources.*`, `taskFunctions.*` | same file → `common` |
| `<plugin id>` | everything of one plugin | `plugins/<name>/locales/<lng>.json`, registered with `i18n.addResourceBundle(lng, pluginId, …)` |

`initI18n`: `defaultNS: 'app'`, `fallbackNS: 'common'`, `interpolation.escapeValue: false`, `returnNull: false`.
The initial language comes from the SQLite prefs injected at boot, falling back to `navigator.language` (anything `zh*` → `zh-CN`, otherwise `en-US`).

## What Rust returns

- **Errors:** `{ code, params }` only. The UI resolves `errors.<code>` in the plugin namespace, then in `common`, and falls back to the raw code.
- **Task logs:** `ctx.log(level, "prefix.event", json!({ … }))`. The UI resolves `logs.prefix.event` in the plugin namespace, then in `common`, else shows `code {params}`.
- **Stages:** `ctx.stage("prefix.phase")` → `stages.prefix.phase`.
- **Enumerations** (kinds, categories, units, statuses) are returned as ids and translated with `t(\`kinds.${id}\`)`.
- **Numbers** that are data (conversions, sizes in a data table) are formatted in Rust. Presentation formatting (e.g. `formatBytes`, dates via `toLocaleString`) may be done in the UI.

## Writing locale entries

```json
{
  "name": "Unit Converter",
  "description": "One sentence shown on cards and in search",
  "help": ["Short usage tips shown in the Help drawer", "…"],
  "functions": { "convert": "Convert" },
  "errors": { "unit.invalid_number": "“{{value}}” is not a number" },
  "logs": { "image": { "file_done": "{{file}} → {{output}} in {{ms}} ms" } },
  "stages": { "image": { "convert": "Converting images…" } }
}
```

- Plurals use i18next suffixes (`key_one`, `key_other`) with `count`.
- Number formatting in interpolation: `{{bytes, number}}`.
- Keep keys identical across languages; write natural copy for each language, not literal translations.
- Brand and technical terms (product name, SQLite, HTTP methods, unit symbols) stay untranslated.
- Names that are also symbols (e.g. 斤) should not be rendered twice (`name · symbol`); compare and show once.

## Enforcement

ESLint for `apps/**/*.tsx` and `plugins/**/*.tsx`:

```js
'i18next/no-literal-string': ['error', {
  mode: 'jsx-text-only',
  'should-validate-template': false,
  words: { exclude: ['[0-9!-/:-@[-`{-~]+', '[A-Z_-]+', '<Brand>', 'SQLite', 'v', '[↑↓↵·−/\\s]+'] },
}]
```

- Only JSX text is checked. Symbols such as `→`, `×` and `/` placed between expressions still count as JSX text, so put them inside a template literal: `` {`${a} → ${b}`} ``.
- Native menus (macOS app menu) are built in Rust, so they get a tiny label table per locale, and the UI calls `app_menu_locale(locale)` whenever `i18n.language` changes.
